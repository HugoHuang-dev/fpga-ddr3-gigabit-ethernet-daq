Project2：原始 200 Mb/s 在另一台 Windows 电脑上的对照测试

目的：保持 FPGA 原始程序和接收程序相同，更换电脑/有线网卡接收路径。
200 Mb/s 尚未通过稳定性验证。本次只做一轮 60 秒抓包测试，结果交回分析；即使通过，也不立即提速。
另一台电脑：建议 Windows 10/11 64 位，管理员权限，优先使用主机自带 RJ45 网口。
不需要安装 Vivado、Python、Wireshark 或编译器。接收程序只依赖 Windows 系统 DLL。

一、文件夹如何转移

1. 把整个 Project2_200M_USB_Kit 文件夹复制到 U 盘。
2. 到另一台电脑后，再把整个文件夹复制到桌面或其他可写的本地目录。
3. 请从本地副本运行，不要直接在 U 盘写抓包。预留至少 3 GB 空间。
4. fpga：原始 BIT 与配套 LTX。receiver：原始 RIO v6 接收程序。
5. 01_Backup_Network.cmd：只读取并保存当前网络配置。
6. 02_Run_Test.cmd：管理员运行，创建本轮日志、抓包和结果，结束时清理本轮临时防火墙放行规则。

二、在当前有 Vivado 的电脑上烧录开发板

1. 开发板保持正常供电。JTAG 下载线连接当前电脑；UART 不需要。
2. 打开 Vivado → Open Hardware Manager。
3. 点击 Open Target → Auto Connect。若已连接，直接在 Hardware 窗口找到 FPGA 器件。
4. 右键 FPGA 器件（xc7a35t）→ Program Device。
5. Bitstream file 选择本文件夹 fpga\project2_v5_top.bit。
6. Debug probes file 选择同文件夹 fpga\project2_v5_top.ltx。
7. 点击 Program，等编程完成，确认没有报错。
8. 按一次开发板 RESET 并松开，等待 DDR 初始化完成，先不要按 KEY0。
9. 保持开发板供电。把开发板网线另一端连接到新电脑自带的 RJ45 网口。
10. JTAG 可以继续留在原电脑，不需要连接新电脑；此轮不需要操作 ILA。

这是通过 JTAG 加载到 FPGA 的程序。开发板断电后可能丢失该程序，应重新执行上述烧录；不要误用板上 Flash 自动启动的其他版本。
原始 BIT 没有后来加的 probe39/40，不要混用 225M/250M 的 LTX。

三、修改新电脑 IP 之前，保存原来的上网配置

1. 新电脑还连接原来的路由器/交换机时，双击 01_Backup_Network.cmd。
2. 看到 BACKUP SAVED 后，确认本文件夹生成 network_backup 子文件夹。
3. 按 Win+R，输入 ncpa.cpl，回车。找到接物理网线的“以太网”。
4. 右键它 → 属性 → 双击“Internet 协议版本 4 (TCP/IPv4)”。
5. 拍照保存当前页面，必须同时包含 IP 和 DNS 两部分。
6. 如果原来手动设置地址，记下 IP、子网掩码、默认网关、首选/备用 DNS。
7. 如“高级”中有多组 IP、网关或 DNS，也保存这些页面；不要删除不明的高级配置。
8. 自动 IP 和自动 DNS 是两个独立选项，分别记录。自动 IP 也可能搭配手动 DNS。
9. 备份内 original_config.txt、dhcp.txt、ipv4.txt、routes.txt、dns.txt 可辅助核对。

四、新电脑设置测试 IP

1. 将新电脑原来接路由器/交换机的网线拔下，接入开发板网线。
2. 保持上述 IPv4 属性窗口打开，选择“使用下面的 IP 地址”。
3. IP 地址：192.168.1.100
4. 子网掩码：255.255.255.0
5. 默认网关：留空。
6. 本测试不需要 DNS。若 DNS 原来自动，保持自动；若原来手动，保留原 DNS 即可。
7. 点击“确定”，再关闭网卡属性窗口。
8. 仅使用这条直连开发板的有线连接做测试。如果其他 Wi-Fi/VPN 连接也使用 192.168.1.x，临时断开并记录，结束后重新连接。
9. 网卡显示“未识别的网络 / 无 Internet”是正常的，这条线只连接 FPGA。
10. 双击以太网查看“速度”，应为 1.0 Gbps；如果仅 100 Mbps 或未连接，先记录该情况，不启动 200M 测试。

五、运行一轮 60 秒测试

1. 在新电脑本地文件夹中，右键 02_Run_Test.cmd → 以管理员身份运行。
2. 脚本会显示所用网卡和速率、RESULTS 保存位置。
3. 提示确认 RESET 时，在板子上按一次 RESET，等待初始化完成，然后在黑色窗口按回车。
4. 脚本先记录环境，结束遗留的 PktMon 抓包，再启动本次抓包。若该电脑正在做其他 PktMon 诊断，请先结束并保存它。
5. 脚本启动 receiver\udp_v5_monitor_rio.exe。
6. 只有看到 ARMED: listening on 192.168.1.100:6666 后，才按一次 FPGA KEY0。
7. 等待 60 秒，不要中途重复按 KEY0 或 RESET，不要手动打开另一份接收程序。
8. FINAL 后，脚本停止并保存抓包，再显示 Press FPGA RESET ...。
9. 按开发板 RESET 停止发送，再回到电脑按回车，等待 PCAPNG 转换完成。
10. 出现 DONE 后可以关闭窗口。PASS/FAIL 都保留，不要删结果，也不需要立即重跑。
11. 将整个 results 文件夹复制回 U 盘，交回原电脑。包含 console.txt、rio_result.json、ingress.etl、ingress.pcapng 以及网卡统计。

说明：脚本仅为该接收程序添加 FPGA 192.168.1.11 → 本机 192.168.1.100 UDP/6666 的临时入站规则，正常退出/报错清理时删除，不关闭系统防火墙。企业策略阻止程序时，保留报错，不要关闭防火墙。
PktMon 没有活动会话时，开始阶段的 stop 提示“未运行”可以忽略。若提示 capture start failed 或其他错误，先保留窗口输出，不要自行改变其他网卡参数。
脚本会添加一个 P2Kit_ 开头的抓包筛选器；筛选器本身不拦截流量、不影响上网。抓包在结束时停止。

六、测试后恢复新电脑上网（务必做）

1. 确认开发板已 RESET 停止发送，测试脚本已经结束。
2. 拔下开发板网线，将主机原来的路由器/交换机网线接回同一网口。
3. Win+R → ncpa.cpl → 同一“以太网”右键“属性” → IPv4。
4. 如果原来 IP 是自动：选择“自动获得 IP 地址”。
5. 如果原来 IP 是手动：根据修改前照片/备份，恢复原 IP、子网掩码和默认网关。
6. DNS 单独按原设置恢复：原来自动就选“自动获得 DNS 服务器地址”；原来手动就恢复原首选/备用 DNS。不要一概改成自动。
7. 点击“确定”保存，恢复之前临时断开的 Wi-Fi/VPN。
8. 等待地址重新获取，再打开网页确认上网。
9. 若原来自动获取地址但暂时没恢复，可以在 ncpa.cpl 中仅对该“以太网”右键“禁用”，然后再“启用”，再等片刻。
10. 若仍不能上网，检查是否接回原网线，及 IPv4/DNS 是否与备份一致。不要使用“网络重置”清除其他配置。

异常关闭脚本后：如果运行窗口被强制关闭，临时规则可能遗留。在“高级安全 Windows Defender 防火墙”→“入站规则”中，仅删除名称以 Project2UsbKit_ 开头的本工具规则。若抓包仍在运行，在管理员终端执行 pktmon stop 保存并停止它。不要清空全部防火墙或抓包规则。
